# Planning (03.15)

## 03.15.01 Policy and Procedures

- SR-03.15.01.a Develop, document, and disseminate to organizational personnel or roles the policies and procedures needed to satisfy the security requirements for the protection of CUI.
- SR-03.15.01.b Review and update policies and procedures [Assignment: frequency].

**Guidance.** This requirement addresses policies and procedures for the protection of CUI. Policies and procedures contribute to security assurance and should address each family of the CUI security requirements. Policies can be included as part of the organizational security policy or be represented by separate policies that address each family of security requirements. Procedures describe how policies are implemented and can be directed at the individual or role that is the object of the procedure. Procedures can be documented in system security plans or in one or more separate documents.

## 03.15.02 System Security Plan

- SR-03.15.02.a Develop a system security plan that:
  - SR-03.15.02.a.01 Defines the constituent system components;
  - SR-03.15.02.a.02 Identifies the information types processed, stored, and transmitted by the system;
  - SR-03.15.02.a.03 Describes specific threats to the system that are of concern to the organization;
  - SR-03.15.02.a.04 Describes the operational environment for the system and any dependencies on or connections to other systems or system components;
  - SR-03.15.02.a.05 Provides an overview of the security requirements for the system;
  - SR-03.15.02.a.06 Describes the safeguards in place or planned for meeting the security requirements;
  - SR-03.15.02.a.07 Identifies individuals that fulfill system roles and responsibilities; and
  - SR-03.15.02.a.08 Includes other relevant information necessary for the protection of CUI.
- SR-03.15.02.b Review and update the system security plan [Assignment: frequency].
- SR-03.15.02.c Protect the system security plan from unauthorized disclosure.

**Guidance.** System security plans provide key characteristics of the system that is processing, storing, and transmitting CUI and how the system and information are protected. System security plans contain sufficient information to enable a design and implementation that are unambiguously compliant with the intent of the plans and the subsequent determinations of risk if the plan is implemented as intended. System security plans can be a collection of documents, including documents that already exist. Effective system security plans reference policies, procedures, and documents (e.g., design specifications) that provide additional detailed information. This reduces the documentation requirements associated with security programs and maintains security information in other established management or operational areas related to enterprise architecture, the system development life cycle, systems engineering, and acquisition.

## 03.15.03 Rules of Behavior

- SR-03.15.03.a Establish rules that describe the responsibilities and expected behavior for system usage and protecting CUI.
- SR-03.15.03.b Provide rules to individuals who require access to the system.
- SR-03.15.03.c Receive a documented acknowledgement from individuals indicating that they have read, understand, and agree to abide by the rules of behavior before authorizing access to CUI and the system.
- SR-03.15.03.d Review and update the rules of behavior [Assignment: frequency].

**Guidance.** Rules of behavior represent a type of access agreement for system users. Organizations consider rules of behavior for the handling of CUI based on individual user roles and responsibilities and differentiate between rules that apply to privileged users and rules that apply to general users.
