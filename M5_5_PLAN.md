## D. Standing constraints (CLAUDE.md Sections 3, 7, 11, in short)

- **Air gap:** no non-loopback network from app code; every HTTP client from `security/net.py`; only Ollama on `127.0.0.1:11434`; no telemetry; no `shell=True`, `eval`, `exec`, shell spawn; every user path through `resolve_within` (`resolve(strict=True)` + `is_relative_to`); Uvicorn on 127.0.0.1 port 0; `X-GRC-Auth` on every route (new routes sit behind `AuthMiddleware`); egress-guard fixture on; no pulls.
- **Models:** exactly two messages per generation request (system + user), `format` schema on every request, strict Pydantic parse, shared budget of 2 attempts, `NEEDS_REVIEW`-style fail-closed on failure; model output may only **lower** a status, never raise it; refuse non-local models.
- **Never:** overwrite a user's input file; mark SUPPORTED without every 8.4 check; add a deployment path for generated infrastructure; add dependencies without approval; commit real company data (all sample data synthetic and labeled); bypass hooks (`--no-verify`, `SKIP=`).
- **Code standards:** Python 3.11, `mypy --strict`, ruff, Pydantic v2 at every boundary, typed domain exceptions mapped to HTTP errors in one place (`api/errors.py`), routers thin, no bare except, logs to local file only.
- **Logging, two tiers, stated without ambiguity.** CLAUDE.md Section 7 says *never log document or questionnaire content above DEBUG*. The first-party code goes further and writes **no content at any level** (the F13-1b practice: "CLAUDE.md allows content at DEBUG, the code writes none"). M5.5 keeps that practice for: customer names, question text, answers, quotes, ledger rows, export row content, **and every identifier from an export (`user.login` included)**. Each feature has a canary test that plants a canary in that content and shows it in **no log record at INFO and at DEBUG** (as F13-1b and F24-3 do). Counts, codes and exception type names are allowed in logs.
- **Vault is read-only for ALIBI.** Nothing in M5.5 writes into the vault; blast radius is a preview on text supplied by the caller and never persisted.
- **Frozen fixtures:** `vault-sample` (M4 goldens) and `vault-demo` + the hostile notes (pinned by `tests/test_eval_freeze.py`; I will re-read how it pins before any new fixture lands) are never edited. ## 1. Scope: the four features

Shared vocabulary: a **promise** is an answer given to a named customer, tied to the policy text that backed it. **Recall** means "flag", never "decide the promise is false".

### 1.1 Reality check (PR 1)
- **What it does:** compares one policy claim with one offline IT export: "Your policy says MFA is required. Your identity export shows 3 users without it."
- **v1 checks exactly this:** **one Okta "MFA Enrollment by User" report CSV and one claim, "MFA required"**. Not "identity, device, cloud reports".
- **Inputs:** the CSV (from the import folder), the vault (read-only), owner-confirmed MFA types, owner-named phone types, owner-confirmed active statuses, the chosen claim sentence, an owner-supplied `exported_at` date.
- **Outputs:** the claim (verbatim quote, path and lines) **shown beside the counts**; export facts (rows, rows per status, in-scope accounts, accounts without MFA, among those how many have `user.isAdmin` true, **the "phone-only" count**, confirmed types "not present in this file", skipped rows by status, file sha256); the exceptions (`user.login`, authenticated response only); a finding `exceptions_found` or `no_exceptions_in_export`; never "compliant".
- **Out of scope:** any live connection, API key or credential (brief non-goal); other claims or formats; inferring service-account exemptions; persisting the export or its rows; writing a report file; **the administrators' hardware-key requirement** (the same sentence as the MFA rule at `access-control-policy.md:23`): a later claim, not v1 (2b, N2).

### 1.2 Promise ledger and recall (PR 2)
- **What it does:** keeps a local record of every answer the owner chose to send to a customer, with the exact policy lines behind it as they were when drafted. Recall re-checks each record against the current vault, on demand, and flags any whose cited lines changed, moved or vanished, or whose policy is now past its review date.
- **Inputs:** a reviewed answers workbook plus a run record (Section 2), a customer choice, a sent date; later, the current vault (read-only).
- **Outputs:** ledger records (Section 3); a recall report: per promise a state (`intact`, `moved`, `changed`, `missing`) plus information flags, reason codes, no model.
- **Out of scope:** sending anything to customers; email or portal integration; deciding a changed promise is false; editing or deleting a promise (append-only; a `voided` event is the only correction); multi-customer workspaces; exporting the ledger to Excel (would need `sanitize.py` and an F23-class review); the M6 approval screen; answer receipts (the ledger stores hashes but claims **no** tamper evidence).

### 1.3 Blast-radius preview (folded into PR 2, deviation M55-3)
- **What it does:** before the owner edits a policy, shows what the edit would break: which promises cite the changed lines (and what state each would move to), which controls the document is mapped to, and which documents link to it.
- **Inputs:** a vault-relative path and the **full proposed new text** of that file (request body, size-capped, never persisted, never written), against the current vault and the ledger.
- **Outputs:** affected promises (customer, state it would move to, reason), controls (ControlMap) with whether another company document covers them, documents that link to it by explicit `[[wikilinks]]` or frontmatter `links`. Pure code, no model.
- **Out of scope:** applying the edit; predicting a model's future answers; semantic similarity; checking the hypothetical text for contradictions; anything written to the vault or index.

### 1.4 Contradiction detector (PR 4)
- **What it does:** finds pairs of company policy statements whose **numbers** disagree (the planted 90 vs 365 day log retention, 35 vs 30 day backups) and shows both quotes with file and lines.
- **Inputs:** the indexed vault (company-policy chunks only); optionally a scope.
- **Outputs:** findings `{finding_id, status, quote_a, source_a path:lines, quote_b, source_b, subject, numbers, flags, reasons}` where `status` is `VALUE_CONFLICT` or `CANDIDATE` and a flag can be `model_not_consulted`; derived on demand, **not persisted and not acknowledgeable in v1**.
- **Out of scope:** framework text against company text (a gap, not a contradiction); withdrawn controls; resolving a conflict; rewriting policy; scope subtleties judged by the machine; persistence of findings. **v1 generates pairs from numeric claims only** (Section 5): conflicts with no numbers (for example "required" against "optional") are not found in v1 (N6).

## 2. Promise creation: Option A, tightened (decided; Q1 to Q4)

Decided: **Option A** (import a reviewed draft workbook), tightened. **Option C** (manual promise entry) stays a later extension; **Option B** (mark a run as sent) stays rejected, because no human reads the text before it becomes a promise.

**What the reviewed workbook supplies:** only the `Review` mark and the final answer text. Everything else comes from **ALIBI's own run record** (Section 3, chunk 2c). The Evidence-cell parser from revision 1 is removed from the design: the Evidence cell is **compared** with what ALIBI wrote, never parsed.

**Import request:** `POST /ledger/import` with: `run_id` (the full hex id, so a renamed workbook still joins its run); `file` (a name inside the export folder, through `resolve_within`; the owner saves the reviewed copy **in place with Save, not Save As**, so it stays in the export folder, 2b N8); the customer choice (below); `sent_on`. The reviewed workbook is read with the existing loader (`read_input_bytes`, `load_questionnaire`: byte scan, caps, same bytes parsed, read-only); the code never saves it (the existing `grc-py-workbook-save-outside-writer` rule already forbids `.save(` outside `writer.py`).

**Where the workbook is read:** the sheet, header row and the first new column come from the **run record**; the six ALIBI header titles must be found where the record says, else the import is refused (`headers_changed`).

**Matching and refusals (whole import):** every question row the run record knows is read from the workbook at the same row number and hashed (the question hash, Section 3). **If any hash differs, or the workbook has fewer or more question rows than the record, the whole import is refused** (`question_mismatch`: sorted or deleted rows, a different workbook): a count of mismatched rows, never text. The question hash is the "rows were not moved" check only; it is **not** the uniqueness key, because a questionnaire can repeat a question (two identical questions have equal hashes at different rows and both must import). Also refused: unknown `run_id`, no run record (`run_record_missing`; a run without a record cannot produce promises), file outside the folder, loader refusals (same codes as `inspect`).

**Per-row skips, each with a reason code and a count (never silent):**

| Code | When |
|---|---|
| `not_approved` | Review is not `approved` (the vocabulary below says how it is counted) |
| `no_answer` | the run record says the row was blank or NEEDS_REVIEW, **or** the Answer cell is blank; includes a blank or NEEDS_REVIEW row the owner filled in by hand (Q4): it has no verified source, so no recall |
| `status_edited` | the Status cell text differs from the hash of what ALIBI wrote |
| `evidence_edited` | the Evidence cell text differs from the hash of what ALIBI wrote (a blank Evidence cell where one was written counts as edited) |
| `baseline_unavailable` | the run record holds no cited-lines hash for that answer (the cited file could not be read at the end of the run) |
| `already_imported` | a promise already exists for this customer, run and **row** (re-import is safe) |

**Review vocabulary (Q3), one definition used in Sections 2, 7 and 9.** Take the cell text; strip **ASCII spaces and tabs only** from both ends; if the result contains any non-ASCII character, or any internal whitespace (extra words), it is **not recognized** and is listed under "other values". Otherwise compare case-insensitively (ASCII): `approved` is approved (so `Approved `, `APPROVED` and a trailing tab are accepted, and the test for a trailing space **expects acceptance**); `rejected` and `unreviewed` are recognized and **counted separately, not stored**; anything else is "other". Every "other" value is reported with its exact text (capped at 64 characters, with a truncation flag) and its count, in the authenticated response only, never logged. A value holding a homoglyph, a non-breaking space or a zero-width character is "other" and is therefore not approved.

**Edit awareness.** The promise stores the Answer cell text as the owner left it (that is what was sent). `edited_after_draft` is true when the sha256 of that cell text differs from the run record's hash of the text **as written to the cell after `sanitize.py`**, so an unedited row never reads as edited, including text that `clean_cell_text` changed (control characters, line endings, length cap). Code cannot tell whether an edited answer still matches its quote; that is a stated limit, the same as F12-2c.

**Owner manual check (STOP L3):** open a draft in Excel, press **Save** (not Save As) without editing any Answer, Status or Evidence cell, and import it; **every row must show `edited_after_draft` false and the import must show no `question_mismatch`**. This is the only way to see whether Excel changes anything my hashes treat as text (line endings, trimming). If it fails, I report it and do not adjust the hashing quietly. **The check needs a draft that has a run record and real SUPPORTED or PARTIAL rows, and I never run a live model, so chunk 2d also builds an offline way to make one** (Section 4, chunk 2d): a scripted model, the real loader, writer and run recorder, over a copy of `vault-demo`, writing a draft and its run record into folders you name. You may choose a live run instead (with `GRC_LEDGER_DIR` set); I never run one.

**Customer (Q6, decided):** the request carries either `{"existing_customer_id": ...}` or `{"new_customer_name": ..., "confirm_new": true}`. A new name without `confirm_new` is refused; a name that normalizes to an existing customer is refused with that customer's id (`customer_exists`). One customer per import. Normalization as in revision 1 (NFC, trim, collapse whitespace, casefold; display name kept as typed, at most 200 characters, control characters refused).

**Sent date (Q7, decided):** owner-supplied `sent_on` (an ISO date). Refused if after `Clock.today()` (`sent_on_in_future`) or before the run record's `created_on` (`sent_before_drafted`).

**Baseline (changed from revision 1).** The promise's baseline is **the policy as it was when drafted**, taken from the run record (the cited lines' hash and the cited file's hash at drafting time). Revision 1's `imported_without_run_record` origin is removed.

**Uniqueness (2b, fix 1):** one promise per customer, run and **row**: `UNIQUE(customer_id, run_id, run_row_index)`. The question hash is deliberately **not** in the key. Test: a run with two identical questions imports both.

## 3. Data model and storage

Wiping the index must never delete promises.

**Config (read from `config.py`):** `Settings` has `vault_dir`, `index_dir`, `questionnaire_dir`, `export_dir`; the overlap check for the last two is a `field_validator` that reads earlier fields from `info.data`, so the new fields must be declared **after** them, and `_dirs_must_be_absolute` must list them. `_is_inside` is lexical; `validate_runtime_dirs` repeats the check on resolved paths. **What the hashes are (exact definitions, in ADR-017):**

NULL when no cell was written.
- `cited_lines_sha256`: sha256 (UTF-8) of the cited lines of the file as the indexer sees it (`decode_and_normalize`, then `split_lines`, lines `start_line..end_line` joined with `\n`, the same rule as `Chunk.text`, `vault/models.py:133`).
- `cited_file_sha256`: the `Citation.file_sha256` the answer carried (the hash of the normalized file as indexed, `questionnaire/models.py:95`). At the end of the run the writer has already compared it with the file's current hash for every cited file (`lower_for_changed_source`, `status.py:193-202`).
- `row_sha256`: over each row's own fields, to detect **accidental** corruption only (no tamper evidence is claimed).

**Append-only is enforced twice:** (1) the repository exposes no update or delete method; (2) SQLite `BEFORE UPDATE` and `BEFORE DELETE` triggers on **every** table `RAISE(ABORT)`. Honest limit: a same-user process can open the file and drop the triggers (O1). Customer names, questions and answers are plaintext at rest (new Section 7 row; the O4 BitLocker assumption applies).

**Run record, chunk 2c (the first change to shipped M5 code).** Facts from the code: `QuestionnaireRuns._execute` (`runs.py:250-301`) answers all questions, calls `write_answers`, then builds a `RunSummary` with counts only; `write_answers` computes each row's final (possibly lowered) result and the stored cell strings **inside** the function and returns an `ExportResult` that holds none of them (`writer.py:68-78`, `:324-333`). So the record needs a small, additive change:
1. `ExportResult` gains one defaulted field carrying, per question row, the data the record needs (row, final status and reasons, the citation, and the three **stored cell strings or their hashes**). Computed where `stored` is already known. Existing callers and tests keep working because the field has a default. The strings never go into `RunSummary`, events or logs.

3. At the end of `_execute`, **after** the file is written, the cited lines' hash is computed with **one read per cited file** through a new public function in `vault/scan.py` that shares `_safe_file`, `_read_limited` and `decode_and_normalize` with `current_file_sha256` (`scan.py:117-136`), returning the file hash and the cited lines' hash from the same bytes. If that file hash differs from `Citation.file_sha256`, the answer's baseline is NULL (`baseline_unavailable` at import).
4. **Ledger folder unset:** the run works exactly as today; the summary gains a warning code `run_record_not_kept` (the summary's `warnings` already carries strings, `runs.py:359`). **Record write fails:** the run still completes, the warning is `run_record_failed`, and a fixed code is logged, never exception text. Existing tests that compare summaries or warnings are re-read first; any needed edit is listed in the PR.
5. **Order:** the record is written after the output file so a record always belongs to a file that exists. A crash between the two leaves a draft with no record; it cannot produce promises (stated in ADR-017).

**Recall detection (pure function `check_promise(promise, current_text | None, today) -> RecallResult`, shared with blast radius).** The caller supplies the text: recall reads the **current vault file** (through the shared read function, never the index, which can be stale); blast radius supplies the proposed text normalized the same way. The text is hashed once and parsed from the same bytes.
1. The text is `None` (file missing, a symlink or junction, outside the root, too big, not UTF-8: the shared read function returns None for all of these, `scan.py:117-136`): `missing`.
2. Take lines `start_line..end_line` of the current text. If their sha256 equals `cited_lines_sha256`: **`intact`**. If the whole file's sha256 differs from `cited_file_sha256`, add the information flag **`document_changed_elsewhere`**. Recall watches the **cited lines only**; this is stated in ADR-017.
3. Otherwise (the cited lines' text differs, including when the quote is still at the same lines): find every place the stored quote occurs (whitespace-normalized verbatim, the `grounding.normalize` rule, nothing else; a new function in `questionnaire/grounding.py` that returns **all** locations over arbitrary text, built on the existing `normalize_with_map`; no existing behaviour changes).
   - Quote found at **other** lines only: **`moved`**, carrying **every** location (start and end line for each).
   - Quote found at the same lines (but the cited lines' text changed) or nowhere: **`changed`** (detail code `cited_lines_changed` or `quote_not_found`). **Never `intact`** when the cited lines' text changed (mutation proof required).
4. Independently: the current frontmatter `review_by` before `Clock.today()`: flag **`review_overdue`** (information, not a state). If the current frontmatter no longer parses, flag `frontmatter_invalid` and say the review date is unknown.

It never calls a model. **Voided promises are excluded from recall and from listings by default** (`include_voided` shows them; history is kept).

Numbers marked "mine" (starting values, flagged for review as M5 did): promises per recall call 2,000; import rows bounded by the existing 500-question cap (`mapping.py:26`); listing page size 100.

## 5. Contradiction detector (PR 4)

**Principle (ADR-013 decision 1, applied here, fail closed as in M5):** code sets the **ceiling** of every finding from facts it checks; the model can keep a finding at its ceiling or lower it, and nothing the model writes can lift a finding above what the code facts allow. **A missing check never gives a stronger result than a check that lowered it** (as in M5, where a missing check never ends SUPPORTED): `VALUE_CONFLICT` needs a valid model verdict as one of its required conditions, the way M5's `SUPPORTED` needs a verified quote, and without a verdict the pair is `CANDIDATE` (2b, N5).

**What is code:**
1. **Chunk selection:** `source_kind == company_policy` chunks only, withdrawn excluded, from the index through the existing repository.
2. **Claim extraction** (regex plus tables, deterministic). A claim is a number with a unit and a subject, found in a sentence **or in a Markdown table row** (the demo's 90-day fact is the row `| Security logs | 90 days |` at `vault-demo/vault/data-retention-policy.md:23`, so a row's first cell is the subject and the other cells carry values; this is a hard test).
   - **Units and kinds (Q12):** *durations*: minutes, hours, days, weeks convert to **days** (minutes ÷ 1,440, hours ÷ 24, weeks × 7); months and years convert to **months** (years × 12). **A days-versus-months pair is a `CANDIDATE`, never `VALUE_CONFLICT`** (a month is not a fixed number of days). *Frequencies* ("once a year", "twice a year", "three times a month"...) are a **separate kind** from durations and are compared only with other frequencies. Other kinds: percent, characters, attempts. **Business days** ("within ten business days", `incident-response-plan.md:22`) are their own unit and are not converted to calendar days (my decision, flagged).
   - **Numbers written as words:** a fixed table for **one through twenty** (and "once", "twice" as frequencies).
3. **Candidate pairs:** two claims, same kind (after conversion), **different values**, **subject-word overlap**; same-document pairs included (Q11). Each claim is compared only with its lexical neighbours (the retriever's FTS5 search) plus a **hard cap on pairs per run, starting at 30**, tuned **on the dev split only** and recorded. The overlap rule must not call "Application logs | 14 days" (`data-retention-policy.md:22`) against "Security logs | 90 days" a `VALUE_CONFLICT`: they share the word "logs" only. This near-miss is a dev item and an offline test.
4. **Verification:** both quotes must be found verbatim (whitespace normalization only, reusing `grounding.py`) in the raw text of the two cited chunks; both chunks company policy; the two chunks may be the same chunk only for a same-document pair with two different lines; each quote meets the length floor (20 characters, 4 tokens, not a heading, `grounding.py:22-23`). The demo's table row `| Security logs | 90 days |` is 27 characters and 7 whitespace-separated tokens (pipes count), so it passes the current floor; a shorter table row would not, and whether a table row needs its own rule is decided at chunk 4a (N6); every number shown is one the code extracted from that quote.
5. **Status:**
   - **`VALUE_CONFLICT`** requires **all** of: code-found numbers of the same kind with different values after conversion; subject-word overlap; **both quotes verified verbatim**; and **a valid model verdict that keeps it** (`conflict` true with relation `same_subject_value_mismatch`). The verdict may only keep or **lower** it (a scope difference such as production versus test lowers it to `CANDIDATE`); it can never lift a pair that fails a code check.
   - **`CANDIDATE`:** everything else that survives verification: a days-versus-months pair, a pair the model lowered (the relation is shown), a pair with lower subject overlap, **and every pair with no valid model verdict**.
   - Anything with an unverified quote is **dropped and counted by reason** (`quote_not_verified`, ...), never shown.
   - **Ollama unavailable (2b, N5, decided):** every code-found mismatch is returned as **`CANDIDATE` with the flag `model_not_consulted`** ("scope not checked by the model"), **never `VALUE_CONFLICT`**. The same rule applies to a pair whose model call failed or whose reply was rejected after the two attempts (my extension, same reason: a missing verdict must never be stronger than a verdict that lowered it).
   - No persistence, no acknowledgement in v1.

**What uses the model:** one question per candidate pair: "do these two statements make incompatible requirements about the same subject, or does a scope difference explain them?" Exactly two messages (system with instructions only; user with the two sources as delimited untrusted data using the existing per-request boundary, `llm/prompt.py` `new_boundary` and `neutralize`), a `format` schema `{conflict: bool, relation: enum[same_subject_value_mismatch, scope_difference, unrelated, unclear], subject (max 120), quote_a (max 400), quote_b (max 400), explanation (max 300), model_confidence}`, `temperature 0`, the shared two-attempt budget (`llm/retry.py`), a **new template with its own hash**, the same gate and non-local refusal. The model's text is untrusted: length-capped, shown only in the authenticated route response, no file write.

**Throughput:** M5 measured about 40 to 60 s per question on the owner's CPU-only laptop. Pair prompts are smaller (unmeasured). The route is a run in the same one-heavy-job slot (409), caps pairs per run, and streams codes and counts only. No design depends on a guessed speed.

**Measurement (like ADR-013):**
- **Files:** `fixtures/eval/contradiction-set.json` and a **new** synthetic vault at `fixtures/vault-contradictions/` (2b, N7; precedent `fixtures/adversarial-m5/vault`; `airgap.yml` already mounts `fixtures/` whole, so **no workflow change**; a path constant is added next to `ADVERSARIAL_M5_VAULT` in `tests/vaultkit.py`, and `fixtures/README.md` gets one line). - **Acceptance, pre-registered now:** (a) offline: both known cases found **as code-found pairs, shown as `CANDIDATE` with `model_not_consulted`** (offline nothing can be `VALUE_CONFLICT`, a hard test), and every planted pair in both splits is a code-found pair (a deterministic count, "n of m"); (b) verification: no finding is ever shown with an unverified quote (a test plus a mutation proof); (c) model step: counts per category ("2 of 3 value mismatches kept", "1 of 4 scope differences wrongly kept"), **no percentages and no targets**. A false `VALUE_CONFLICT` on a `no_conflict` item is recorded and is a tuning candidate unless a deterministic check misfired. "No known contradiction" in answers (ADR-013 decision 13) is **not** changed by M5.5.

## 9. Testing rules

Every chunk: tests first or with the code; at least one negative/security test; all offline (egress guard on; mock transport or an unused loopback port; the port-11434 guard); fixtures built by code where binary (no committed binaries); synthetic data labeled. Mutation proof procedure (as M5): break the control with the edit tool, show the named test run and its "N failed", restore byte for byte and show the matching sha256; record in the ADR table with limits; each test built so only the control can make it pass; every scenario has a 30 s limit (deviation 42).

**Where mutation proofs matter most** (a miss means a false assurance, a lost record or a silent wrong count):
- **Append-only:** remove each trigger; add an update method; tests must fail.
- **Run record:** swapped model digest or template hash; the stored cell hash taken **before** `sanitize.py` instead of after (an unedited row would read as edited; fails the sanitize-heavy fixture); the cited lines' hash read from the wrong range; the cited file hash not compared.
- **Import gate:** accept a non-exact Review value (non-ASCII, extra words); **reject** `approved ` with a trailing space (the test expects acceptance, so this proof fails the acceptance test); skip the question-hash match; skip the Status or Evidence comparison; create from a NEEDS_REVIEW or blank row; skip the sent-date or customer validation; allow a new customer without `confirm_new`; allow a duplicate (customer, run, **row**); **key uniqueness on the question hash instead of the row (the second of two identical questions would then be skipped as `already_imported`; the two-identical-questions test must fail)**; import without a run record.
- **Recall change detection:** skip the cited-lines hash compare; treat `moved` as `intact`; **quote still at the same lines but the lines' text changed returns `intact`** (must fail); drop the `document_changed_elsewhere` flag; report one location when several exist; read the index instead of the vault; ignore a missing file. Highest priority: a missed change leaves a false promise unflagged.
- **Voided:** a voided promise still appears in recall or listings by default; a `voided` event that edits a row instead of appending.
- **Reality check counting:** use `authenticators.count`; let email or password count as MFA; count a non-Active user; treat a blank type cell as enrolled; **refuse a confirmed type that is not present in the file (the default set on a file with no security-key user must still run)**; **count a user with an MFA type besides phone as phone-only, or leave a phone-only user out of the count**; **count a user with an empty intersection (no MFA-capable type at all) as phone-only (this must fail a test)**; off-by-one; drop each cap; accept an unlisted encoding; skip the verbatim check of the claim quote; keep a non-allowed column; log a `user.login`.
- **ControlMap:** `AC-2` matching `AC-20` (substring match must fail the negative test); the child rule reversed; plus the identical-M4-goldens evidence (no file under `retrieval/` or `repositories/` changed, `git diff --stat` shown, and `test_retrieval_golden.py` passes).
- **Detector:** casefold the verbatim match; skip the cited-in-context check; skip the code-extracted-numbers requirement; let model output raise `CANDIDATE` to `VALUE_CONFLICT`; **return `VALUE_CONFLICT` without a model verdict (Ollama unavailable, a failed call, a reply rejected twice): this must fail a test, and offline no pair may ever be `VALUE_CONFLICT`**; convert days-versus-months as if a month were 30 days (a days-versus-months pair must stay `CANDIDATE`); compare a frequency with a duration; include framework or withdrawn chunks; skip the pair cap; call "Application logs 14 days" against "Security logs 90 days" a `VALUE_CONFLICT`.
- **Path guards, root overlaps and no-network:** one proof each (skip `resolve_within`; drop the ledger, import or export overlap check; allow a network import).
- **Logging canaries:** log a customer name, a question, a `user.login` at INFO.

**Lighter proofs are enough** (a negative test or one mutation): response-model shapes and field names; route wiring and auth (one proof per route family, like `test_questionnaire_routes_require_token`); config validators beyond the overlap rule; customer-name cosmetic normalization; CSV quoting and delimiter examples; fixture integrity; pure formatting of reason codes.

## L. Edit-tool-only hook (Q16: DEFERRED on 2026-10-13 until API credits are replenished; own PR `m55-edit-only-hook`, kept here as the design for later)

**Status: deferred (M55-2). Nothing is implemented.** Section 4 no longer schedules the hook PR. Because the hook gates my own shell commands once active, I enable and test it last in its own PR.

**Goal.** Turn CLAUDE.md Section 2 rule 9 ("edit tool only, never sed, heredocs or stdin scripts") into a technical control in `.claude/settings.json`.

**Documentation read on 2026-10-12** (revision 1; not re-read in this revision): `https://code.claude.com/docs/en/hooks` (first 100,000 of 268,801 characters only) and `https://code.claude.com/docs/en/permissions` (keyword search only). I re-read `.claude/settings.json` in this session: it has `allow`, `ask` and `deny` lists and `defaultMode: plan`, and no `hooks` key.
- Hook config: `hooks.PreToolUse[]` = `{matcher, hooks:[{type:"command", command, args?, timeout?, onFailure?}]}`. `args` runs exec form with no shell. `${CLAUDE_PROJECT_DIR}` is available. Stdin JSON carries `tool_name`, `cwd`, `tool_input.command`.
- Exit 2 blocks (stderr goes to the model). Exit 0 with `hookSpecificOutput.permissionDecision:"deny"` also blocks. **Any other exit code, a crash, a timeout, a missing script or invalid JSON fails open.** `"onFailure":"block"` makes failures block (docs say v2.1.295 or later).
- Permission rules: order deny, ask, allow. Compound commands split on `&&`, `||`, `;`, `|`, `|&`, `&`, newlines and each part must match. Docs call argument-constraining Bash patterns fragile. Output redirects are checked against `Edit` rules, so denying `Edit` would also block the edit tool. A hook "allow" cannot override a deny rule; a hook deny blocks.

**Conclusion: deny rules alone cannot do it. A PreToolUse hook script is needed.**

**Proposed design**
- Entry (additive; existing `deny` list untouched): `matcher: "Bash|PowerShell"`, `command` = Python (stdlib only, run with `-I`), `args` = path to script, `timeout: 10`, `onFailure: "block"`. The interpreter path must resolve from the project dir (the sketch used a relative `.venv` path, not final).
- Script `tools/hooks/no_shell_writes.py` (covered by ruff, mypy --strict, Bandit). Tests `sidecar/tests/test_no_shell_writes_hook.py`, running the script as a subprocess with JSON on stdin.
- Quote-aware scanner (single quote, double quote, `$(...)`). Blocks with exit 2 and a stderr reason: (1) unquoted `<<`, `<<-`, `<<<`; (2) `sed` with `-i`, `--in-place`, a short-flag cluster containing `i`, a `w`/`W` command, or an output redirect; (3) unquoted `>`, `>>`, `&>`, `N>`, `N>>` into the repository (`/dev/null`, `&1`, `&2` always allowed, so `2>&1` works); (4) `tee` with file arguments; (5) PowerShell `Set-Content`, `Add-Content`, `Out-File`, `New-Item -Value`, here-strings `@'` and `@"`; (6) inline interpreters `python -c`, `python -`, `node -e` containing `open(` or `write`; (7) `cp`, `mv`, `Copy-Item` and `Move-Item` whose destination is inside the repository (added 2026-10-13 after deviation M55-1), with a must-block test for each of the four and a must-allow test for a copy to an absolute path outside the repository.
- Allowed unchanged: git, pytest, ruff (including `ruff format`), cargo (including `cargo fmt`), pnpm, grep, cat, `sed -n` for reading.
- **Known gap, to state in the ADR and threat model:** a guardrail against the model, not a sandbox; a determined route (an interpreter or build tool that writes) cannot be fully closed by text inspection.
- **New consequence for this plan:** the docs-PR recount and tally scripts (Section 0) and the M5.5 tooling write files **outside** the repo by running a script written with the write tool; the hook's redirect rule (block into the repository, allow absolute paths outside it) leaves that route open, which is the intended behaviour (decision 1 below).

**Owner decisions (2026-10-12)**
1. Redirects: block into the repository; allow absolute paths outside it (the review workflow writes diffs to Downloads); a target that cannot be resolved is blocked. Alternative: `git diff --output=<path>` and block all redirects except `/dev/null`; **decide at build time.**
2. Inline interpreters: include the `python -c` / `node -e` `open()`/`write` rule.
3. `<<` inside quotes (for example a commit message): allowed.

**First steps when building:** run `claude --version` and confirm `onFailure` support (v2.1.295 or later; if older, report that exit 2 on internal errors is the only protection and a missing script or timeout fails open); confirm in the docs that `PowerShell` is a valid matcher name.

**Test cases (at least 5 blocked, 5 allowed; about 15 planned).** Must block: `cat > notes.md <<'EOF' ... EOF`; `git commit -m "$(cat <<EOF ... EOF)"`; `sed -i 's/a/b/' f.py`; `sed -Ei ...` and `sed --in-place ...`; `sed 's/a/b/' f > out.py`; `echo x >> README.md`; `pytest | tee log.txt`; `ruff check . > out.txt`; `Set-Content -Path a.md -Value x`; `python -c "open('a','w').write('x')"`; a redirect with an unresolvable target; an unterminated quote. Must allow: `git status`; `git diff HEAD~1`; `.venv/Scripts/python -m pytest 2>&1`; `.venv/Scripts/python -m ruff format --check . ../tools --config pyproject.toml`; `cargo fmt`; `cargo clippy --all-targets -- -D warnings`; `grep -rn "a > b" src`; `cat file.md`; `sed -n '1,20p' f.py`; `ruff check . 2>/dev/null`; `git commit -m "feat: handle a<<b case"`; a redirect to an absolute path outside the repository. **Fail closed, script level:** top-level handler exits 2 on any exception, invalid or empty stdin JSON, or missing `tool_input.command` (tests: garbage stdin, empty stdin, a patched parser that raises; mutation: change the handler to exit 1 and show the test fail). **Fail closed, harness level:** with `onFailure:"block"`, point `command` at a nonexistent script, run `git status`, confirm it is blocked; show the output, revert.

**Shipping:** new branch off `main` with the script, tests, the `hooks` addition, a short ADR, **ADR-015** (the number stays reserved for it; the PR is deferred, M55-2, so it may merge after ADR-016 to ADR-019; no letter suffix), a one-line pointer in CLAUDE.md Section 2 rule 9 (the drift test compares Sections 3, 7 and 11 only; rule 9 is none of them, so no Cursor or CodeRabbit mirror). Local checks per Section C. Order: tests, script, full suite, live fail-closed proof, show the diff, commit with no `Co-Authored-By`. Small PR, merged without CI, local output pasted.
